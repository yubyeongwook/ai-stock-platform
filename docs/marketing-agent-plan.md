# 한국 마케팅 시장 정복 플랜 — 올인원 AI 마케팅 에이전트

**브랜드**: 매출엔진 — "블로그 개수가 아니라 매출로 증명하는 마케팅"

작성일: 2026-08-24 (v2, 기존 v1 계획 폐기 후 재작성)

## 0. 방향 전환

v1 계획은 `ai-stock-platform` 하나만을 위한 브리핑 콘텐츠 마케팅이었다. 목표를 다시 정의한다:

> **하나의 서비스를 홍보하는 마케터가 아니라, "블로그 + 웹 + 플레이스(로컬 검색)"를 무기로 어떤 고객사든 마케팅을 대행·집행할 수 있는 올인원 AI 마케팅 에이전트 조직을 만들어 한국 마케팅 시장을 장악한다.**

핵심 산출물 3종은 고정한다.
1. **블로그를 업계 최고 수준으로** — SEO 콘텐츠 생산·최적화
2. **웹(홈페이지/랜딩페이지)을 최고로** — 전환 잘 되는 웹 제작·개선
3. **"특정한 곳"을 고객이 먼저 찾게 만드는 마케팅** — 플레이스/로컬 검색(네이버 플레이스·지도·리뷰) 최적화, 즉 병원·매장·지역 비즈니스가 검색에서 상위 노출되게 만드는 것

이 3종은 전부 유기(organic) 채널이라 반영까지 시간이 걸린다. 여기에 **메타(페이스북·인스타그램) 광고 연결**을 유료 리타겟팅 레이어로 얹는다 — 블로그·랜딩페이지를 방문했지만 전환하지 않은 사람을 다시 잡아오는 역할로, 2절의 9번째 에이전트가 담당한다.

## 1. 사업 포지셔닝

- **형태**: AI 에이전트가 콘텐츠 생산·최적화를 상시 자동화하고, 사람은 전략/영업/규제 검수만 담당하는 경량 마케팅 대행사
- **아키텍처 원칙**: 업종마다 시스템을 따로 만들지 않는다. 9개 에이전트는 모든 업종에 공통인 **코어 엔진**이고, 업종별로 달라지는 건 금지어·톤·컴플라이언스 체크리스트 같은 **업종 모듈**뿐이다 — 업종을 늘릴 때 코어를 새로 짜지 않고 모듈만 추가한다
- **시작 버티컬**: **음식점 + 노무법인**부터 (v3에서 변경 — 이전엔 "병원부터"였으나, 코어 엔진을 규제 부담 없이 먼저 검증하는 쪽을 택함). 병원·의료(치과 포함)는 Compliance 게이트가 별도로 필요해 코어가 검증된 뒤 확장한다 — 치과 접근권한은 있지만 의도적으로 지금 쓰지 않고 보류. 근거와 트레이드오프는 [`docs/north-star-vision.md`](./north-star-vision.md) 4절 참고
- **차별점**: 사람 대행사 대비 3~5배 빠른 콘텐츠 산출 속도 + 매주 자동 성과 리포트로 이탈 방지 + 업종별 규제 준수 템플릿 선점
- **주의**: 위 차별점(블로그·플레이스·웹 자동화)만으로는 한국 대행사 수천 곳이 이미 파는 상품과 다를 게 없다. 시간이 지나도 못 베끼는 진짜 해자는 [`docs/competitive-moat.md`](./competitive-moat.md) 참고 — 데이터 플라이휠, 초고속 실험 루프, 업종 플레이북 자산화, 성과 연동 가격 4가지
- **최종 목표(확정)**: 사장님이 직접 가입·구독하면 그 티어에 맞는 마케팅이 자동으로 돌아가는 **구독형 SaaS**. 지금 이 문서의 1인+9에이전트 에이전시 모델은 그 목적지가 아니라, SaaS 상품의 핵심 경쟁력(업종 플레이북·콘텐츠 품질 기준)을 고객 돈으로 먼저 검증하는 단계다. 구체적인 SaaS 구조(구독 티어별 자동화 범위, 네이버 API 부재를 어떻게 우회할지)는 [`docs/north-star-vision.md`](./north-star-vision.md) 7절 참고 — 착수는 고객 6곳+ 넘어가는 시점(2절 확장 기준) 이후

## 2. 팀 구성: 몇 명(개)이 필요한가

**AI 에이전트 9개(4개 서비스 라인 + 오케스트레이터) + Human 1명(나 혼자)**으로 시작한다.

### 서비스 라인별 AI 에이전트

| 라인 | 에이전트 | 역할 |
|---|---|---|
| 블로그 | 블로그 콘텐츠 에이전트 | 키워드 기반 SEO 블로그 포스트 초안 생성 |
| 블로그 | 블로그 최적화 에이전트 | 제목·썸네일·내부링크·발행 주기 최적화 |
| 웹 | 랜딩페이지 카피 에이전트 | 전환 중심 웹/랜딩페이지 문구·구조 초안 |
| 웹 | 전환최적화(CRO) 에이전트 | A/B 테스트 문구·레이아웃 제안 |
| 플레이스 | 로컬 SEO 에이전트 | 네이버 플레이스·지도 노출 체크리스트, 등록정보 최적화 |
| 플레이스 | 리뷰·리텐션 에이전트 | 리뷰 유도·대응 + 카카오톡 채널로 예약 리마인더·재방문 유도 (리텐션 담당) |
| 유료광고 | 메타 광고 운영 에이전트 | 페이스북·인스타그램 리타겟팅 광고 소재·타겟 운영, 방문 후 이탈자 재유입 |
| 공통 | 성과 분석 에이전트 | 채널별 지표 자동 리포트, 개선 우선순위 제안 |
| 공통 | 오케스트레이터 에이전트 | 고객사별 캠페인 캘린더 관리, 산출물 품질 검수 큐잉 |

### Human 1명 (나) — 1인 3역

AM/QA/총괄 검수를 별도로 채용하지 않고, 9개 에이전트가 만든 산출물의 최종 승인·영업·규제 검수를 전부 혼자 수행한다.

| 역할(모자 3개) | 담당 |
|---|---|
| 총괄 검수 | 브랜드 톤 최종 승인, 업종별 규제(노무사법상 소개·알선 제한 등) 검수 |
| 영업/고객성공 | 신규 고객 영업, 온보딩, 고객 커뮤니케이션 |
| 콘텐츠 QA | AI 산출물 팩트체크·오탈자 검수 (특히 노무법인 등 전문직 규제 업종) |

확장 기준(rule of thumb): 혼자서 병목 없이 감당 가능한 동시 고객사는 **3~5곳** 수준. 오케스트레이터 에이전트가 산출물을 큐잉·1차 스크리닝해 내가 검수할 양을 줄여주는 것이 핵심이며, 이 한도를 넘으면(고객사 6곳+) 그때 처음으로 사람(AM 또는 QA) 채용을 검토한다 — 그 전까지는 AI 에이전트 9개만으로 확장한다.

## 3. 실행 로드맵

- **Phase 0 (1~4주) 파일럿**: **파일럿 2곳 확보 완료** — 음식점(직접 관리), 노무사무실(소속). 콜드아웃리치 불필요, 접근권한이 이미 있어 브리프 수집부터 바로 시작. 치과는 접근권한이 있지만 **의도적으로 보류** — Compliance 게이트 없이 진행하면 리스크가 크므로 Phase 3까지 미룬다(`docs/operator-checklist.md`의 치과 전용 가드레일은 그때 다시 씀). 메타 광고는 아직 붙이지 않는다(계정·소액 예산 준비가 필요해 착수가 늦음, 우선 유기 채널로 사례부터 만든다)
- **Phase 1 (5~10주) 첫 유료 고객**: 파일럿 사례로 세일즈 자료 제작, 유료 고객 5곳 확보. 블로그+플레이스부터 먼저 판매(웹 제작보다 착수 빠름). 파일럿에서 전환율이 검증된 고객 1곳에 메타 리타겟팅을 시범 연결
- **Phase 2 (11~20주) 버티컬 템플릿화**: 음식점·노무법인 등 업종별 콘텐츠·규제 체크리스트 라이브러리화, 고객 5곳까지 혼자 운영해보며 병목 지점 파악 → 6곳 이상이면 그때 처음 채용 검토
- **Phase 3 (21주~) 시장 장악**: 사례 기반 인바운드 영업 전환, 업종 확장(치과부터 — 접근권한이 이미 있어 Compliance 게이트만 준비되면 바로 착수 가능, 이후 병원·의료 일반/미용실/학원 등), 지역 확장

### 전체 6단계 (사업 Phase + SaaS 전환을 합친 최종 로드맵)

위 Phase 0~3(사업/영업 기준)과 `docs/north-star-vision.md`의 SaaS 전환을 하나로 합치면 총 6단계다. 지금 위치는 **1단계 착수 직전**(코드·문서는 준비됐고 실제 파일럿 고객이 아직 0곳)이다.

| 단계 | 이름 | 핵심 작업 | 대응 Phase |
|---|---|---|---|
| 1 | 코어 엔진 검증 | 파일럿 3곳, LLM 연결, 수동 발행 | Phase 0 |
| 2 | 첫 유료 전환 | 유료 5곳, 카카오·메타 연동 실제 검증 | Phase 1 |
| 3 | 업종 플레이북 자산화 | 고객 20곳, 업종별 템플릿 라이브러리화 | Phase 2 |
| 4 | 미니 대시보드 | 고객 6곳+ 트리거 시 큐관리+승인버튼(6절), 아직 나 혼자 쓰는 내부 도구 | Phase 2 종료 시점 |
| 5 | 멀티테넌트 SaaS 전환 | `clients/*.json`→DB화, 구독자 자기 온보딩, 원클릭 발행 UI, 티어별 자동화 | north-star-vision.md 7절 |
| 6 | 업종 확장·시장 장악 | 병원 등 규제업종 추가, 지역 확장, 인바운드 전환 | Phase 3 |

우리 대행사 매출이 실제로 어떻게 늘어나는지(가격 구조, 3개 성장 루프, Phase별 매출 가정치)는 [`docs/revenue-model.md`](./revenue-model.md) 참고.

우리가 하는 작업이 **고객사(음식점·노무법인 등)의 매출**을 어떤 매커니즘으로 늘리는지(노출×클릭×전환 퍼널, 배수별 담당 에이전트)는 [`docs/client-revenue-funnel.md`](./client-revenue-funnel.md) 참고.

## 4. 핵심 KPI

- 고객사 신규 계약 수 / 이탈률(Churn)
- 고객사별: 블로그 발행 후 유입 세션, 플레이스 노출·클릭수, 웹 전환율
- 내부: 에이전트 산출물 1차 승인율(사람 QA 통과율) — 낮으면 템플릿 개선 신호

## 5. 리스크 및 대응

### 자동화 레벨 — 뭘 AI 혼자 하게 두고, 뭘 사람이 봐야 하는가

모든 에이전트 산출물이 같은 검수 강도를 받을 필요는 없다. 위험도에 따라 3단계로 나눈다.

| 레벨 | 예시 | 처리 방식 |
|---|---|---|
| 1 — 완전 자동 | 데이터 수집, 경쟁사 모니터링, 키워드 분석, 성과 리포트, KPI 계산 | 사람 검수 없이 바로 반영 |
| 2 — AI 생성 + 사람 승인 | 블로그, SNS, 광고 문구, 카카오 메시지, 랜딩페이지 카피 | AI가 만들고 내가 승인해야 발행 (지금 대부분의 작업이 여기) |
| 3 — 사람 필수 | 규제 업종 최종 판단(노무사법 등), 계약, 광고비 대규모 증액, 전략 변경 | AI는 추천만, 결정은 항상 사람 |

- **업종별 규제 위반 리스크**: 업종별 규제 체크리스트를 콘텐츠 에이전트 프롬프트에 하드코딩, 레벨 3 게이트로 설정. **노무법인**: 공인노무사법 제27조의2 확인 완료 — 1항은 사건 수임과 관련한 대가를 전제로 한 소개·알선·유인을, 2항은 노무사 고유 업무의 보수·이익을 비노무사가 나눠 갖는 것을 금지한다. 핵심 기준은 **과금이 사건 수임·문의 건수에 연동되는지**다. 정액(산출물 기준) 또는 광고비 집행액 비례 수수료는 안전, 문의·수임 성사 건당 커미션은 금지 — 그래서 계약 범위를 "콘텐츠·광고 제작 대행"으로만 한정하고 성과연동(건당) 과금은 설계에서 아예 뺀다(`docs/competitive-moat.md` 4절)
- **네이버 알고리즘 의존 리스크**: 블로그·플레이스·웹(자체 도메인 SEO)로 채널 분산해 특정 플랫폼 리스크 완화
- **AI 콘텐츠 품질 편차**: 고객사 계약 전 반드시 파일럿 산출물 샘플 승인 절차를 거침
- **메타 광고 정책 리스크**: 메타는 건강 상태·질병 등 민감정보 기반 타겟팅을 제한한다. 지금 시작 버티컬(음식점·노무법인)엔 해당 없지만, Phase 3에서 병원·의료를 붙일 때 리타겟팅 세그먼트 설계에 레벨 3 게이트를 반드시 둔다

## 6. 기술 인프라: 웹이 필요한가

**결론: 지금은 필요 없다.** 지금 구조는 내가 오케스트레이터 역할을 겸해 `blog_content_agent.py` 등 스크립트 결과물을 직접 돌려보고 Notion/구글시트에 수동으로 옮기는 방식이며, 파일럿 1~3곳 규모에서는 이걸로 충분하다.

**웹(대시보드)이 필요해지는 트리거**: 아래 중 하나라도 해당되면 그때 만든다.
- 동시 고객사가 6곳을 넘어 수동 복사·붙여넣기가 병목이 될 때 (2절의 채용 검토 임계값과 동일 시점)
- 고객에게 진행 현황을 셀프로 보여줘야 영업에 도움이 될 때(경쟁 대행사 대비 차별화 포인트로)

**만들 때의 형태**: 이 환경에 이미 있는 Vercel(배포)+Supabase(DB·인증) 조합을 그대로 쓴다.
- 큐 관리 화면: 오케스트레이터 에이전트의 태스크 큐를 시각화 (지금 문서 0절의 파이프라인을 그대로 UI화)
- 승인 버튼: 내가 매번 스크립트를 직접 실행하는 대신, 산출물을 보고 승인/반려만 클릭
- 고객사별 상태 페이지: 필요 시 고객에게 공유

## 7. 상세 스펙

각 에이전트의 필요 구성(인풋·도구·아웃풋)과 단계별 업무 프로세스는 [`docs/agent-specs.md`](./agent-specs.md) 참고.

내(사람)가 Phase 0을 시작하기 위해 지금 해야 할 일과 필요한 계정·도구는 [`docs/operator-checklist.md`](./operator-checklist.md) 참고.

## 8. 참고 구현

- `content_playbook.py`: **코어 엔진의 실질적 해자** — 4U 헤드라인 공식, 네이버 SEO 구조 원칙, 전환심리학 원칙을 코드 자산으로 담은 노하우 라이브러리. `blog_content_agent.py`·`integrations/llm_writer.py`가 참조한다 (`docs/competitive-moat.md` 3절)
- `blog_content_agent.py`: 업종 무관 SEO 블로그 초안 생성기 (블로그 라인), 제목은 `content_playbook.py`의 헤드라인 공식으로 생성
- `local_place_agent.py`: 로컬/플레이스 마케팅 체크리스트·문구 생성기 (플레이스 라인)
- `marketing_content_agent.py`: 금융/증권 버티컬용 일일 브리핑 콘텐츠 생성기 (v1에서 이어지는 특정 버티컬 예시)
- `orchestrator.py`: 고객사 브리프(`clients/*.json`)를 받아 블로그·플레이스 초안을 생성하고, 카카오 알림톡·메타·GA4 연동을 설정된 만큼만 시도하는 실행 스켈레톤. 크리덴셜 없이도 콘텐츠 뼈대 생성 부분은 바로 동작한다
- `business_dna.py` / `master_ai.py`: north-star-vision.md의 Business DNA·Master AI 개념을 미리 만든 최소(규칙 기반) 버전 — 업종 자동 프로필링, 치과 등 보류 버티컬 코드 레벨 차단, 퍼널 병목 진단. 자세한 한계는 `docs/north-star-vision.md` 9절 참고
- `tests/`: 53개 테스트로 전체 파이프라인 검증(`pip install -r requirements-dev.txt && pytest`). 이 테스트를 짜다가 실제 버그 하나를 잡았다 — `ga4_client.py`가 패키지 미설치 시 `GA4ConfigError` 대신 `ModuleNotFoundError`를 새어나가게 해서 `orchestrator.py`가 죽을 수 있었음(수정·회귀테스트 완료)
- `performance_log.py`: **3단계(업종 플레이북 자산화) 재료를 받는 그릇** — 실제 성과가 최소 3건 쌓이면 `master_ai.py`의 가정 벤치마크를 실측치로 교체하자고 제안한다. 지금은 데이터 0건, 로직만 준비됨
- `status_dashboard.py`: **4단계(미니 대시보드)의 지금 버전** — Vercel+Supabase 없이 `clients/*.json`+`outbox/`만 읽어 정적 HTML 상태판을 로컬 생성한다(`python status_dashboard.py` → `status.html`). 진짜 웹 대시보드는 여전히 6절의 트리거(고객 6곳+) 이후
- `docs/saas-db-schema-draft.sql`: **5단계(SaaS 전환) 스키마 설계 초안** — 실제 Supabase 프로젝트는 아직 프로비저닝 안 함, 착수 시점에 그대로 적용할 수 있게 설계만 해둠
- `business_dna.py`의 6단계 대비 프로필: 병원 일반·미용실·학원·법무법인/세무법인을 미리 등록해뒀으나 전부 `active: False` — 법 조문 검증 전에는 콘텐츠 생성 자체가 코드로 막힘
- `docs/quote-template.md`: 2단계(첫 유료 전환) 견적서 템플릿, `service-agreement-template.md`와 짝
- `.github/workflows/ci.yml`: 푸시할 때마다 테스트 45개 자동 실행
- `.github/workflows/generate-content.yml`: GitHub Actions 시크릿(`ANTHROPIC_API_KEY` 등, 이름은 `.env.example`과 동일해야 함)으로 `orchestrator.py`를 실제 실행 — 지금은 수동 실행만(비용 발생 가능해서 자동 스케줄은 파일럿 검증 후 추가). 산출물은 워크플로 아티팩트로 다운로드
- `integrations/`: 카카오 알림톡·메타 광고·GA4·LLM(클로드) 연동 클라이언트. `.env.example` 참고. 카카오·메타·GA4는 계정 발급(본인 명의·사업자 인증 필요, 내가 대신 못 함)이 남아있고, **LLM(`llm_writer.py`)은 `ANTHROPIC_API_KEY`만 넣으면 바로 실제 블로그 본문을 써준다** — API 키 미설정/오류 시에도 죽지 않고 뼈대만 출력하며 이유를 파일에 남긴다(검증 완료)
