# 온보딩 브리프 양식

파일럿 고객사(음식점·노무사무실 등)에게 실제로 받아야 할 정보를 정리한 질문지다. `docs/operator-checklist.md` 3절의 최소 정보 목록을 실제로 채워 넣을 수 있는 형태로 구체화했다. 이 문서를 그대로 카카오톡/메일로 보내거나, 읽으면서 인터뷰해도 된다.

작성된 답변은 그대로 `clients/*.json`의 필드로 옮긴다 — 아래 각 질문 옆에 대응하는 필드명을 표시해뒀다.

---

## 1. 기본 정보

1. 상호명이 정확히 어떻게 되나요? → `business_name`
2. 업종을 한 단어로 표현하면? (예: 고깃집, 노무법인, 카페) → `category`
3. 주소는 어떻게 되나요? (지번·도로명 둘 다, 네이버 등록용)
4. 대표 전화번호는? (플레이스·문의용)
5. 어느 동네/지역으로 검색되길 원하시나요? (예: "강남", "역삼") → `location`

## 2. 타겟 고객

6. 주로 어떤 분들이 찾아오시나요? (연령대, 상황 — 예: "회식 손님 많음", "퇴직금 문의가 제일 많음")
7. 지금 제일 아쉬운 부분은 뭔가요? (신규 유입 부족 / 재방문 부족 / 특정 메뉴·서비스 홍보 등) → `master_ai.py` 진단의 출발점이 됨

## 3. 키워드

8. 고객이 검색할 때 어떤 단어로 찾아올 것 같나요? 2~3개만 적어주세요 (예: "강남 회식", "퇴직금 계산") → `keywords`
9. (있다면) 지금까지 반응이 좋았던 메뉴·상품·서비스는?

## 4. 기존 자료

10. 기존 블로그·인스타그램·홈페이지 URL이 있나요? (없으면 없다고)
11. 사진 자료를 최소 10장 보내주실 수 있나요? (내부·외부·메뉴·시술/서비스 장면 등)

## 5. 금지·주의 표현

12. 콘텐츠에 **절대 쓰면 안 되는 표현**이 있나요? (업계 관행, 개인적으로 싫어하시는 문구 등) → `banned_terms`
13. (노무사무실인 경우) 사건 소개·알선으로 오해될 수 있는 표현은 저희가 이미 기본값으로 제외해뒀습니다(`business_dna.py` 참고) — 추가로 걸리는 표현이 있으면 알려주세요
14. (첫 방문 혜택이 실제로 있다면) 어떤 혜택인가요? 없으면 없다고 — 없는 걸 지어내지 않습니다 → `first_visit_benefit`

## 6. 운영

15. 콘텐츠 발행 전 검토·승인은 누가 하나요? 연락 가능한 채널은? (카카오톡/문자) → `review_target_phone`
16. 발행 주기는 어느 정도를 원하시나요? (주 1회? 격주?)

---

## 브리프 → `clients/*.json` 매핑 예시

위 답변을 받으면 아래 형태로 옮긴다 (`clients/example-restaurant.json` 참고):

```json
{
  "slug": "고유-식별자",
  "business_name": "질문 1",
  "category": "질문 2",
  "location": "질문 5",
  "keywords": ["질문 8"],
  "review_target_phone": "질문 15",
  "banned_terms": ["질문 12, 13"],
  "ga4_property_id": null
}
```
